2Investigar la cuarentena10 min

Qué estás mirandoAntes de corregir nada hay que entender por qué fallan las filas. La columna motivo dice qué regla se incumple; cruzar con otras tablas dice de dónde vienen, y eso suele señalar la causa.
  1. SQL
    SELECT aircraft_id, model, manufacturer, engine_model,
       cycles_total, hours_total, motivo
FROM lab1002.cuarentena.dim_aircraft
ORDER BY aircraft_id;
    Deberías verSiete filas. Dos Boeing sin horas válidas (una vacía y otra en -1), un A320 y un E190 sin motor, y el A00024 repetido con dos matrículas distintas.
  2. SQL
    SELECT q.motivo, r.source_system, count(*) AS filas
FROM lab1002.cuarentena.fact_engine_sensor AS q
LEFT JOIN lab1002.silver.dim_sensor_reading AS r USING (reading_id)
GROUP BY ALL
ORDER BY q.motivo, filas DESC;
    Deberías verUn patrón claro: 4 de las 6 altitudes imposibles vienen de RECORDER_TEST y 4 de las 6 velocidades imposibles de ACMS_LEGACY. El resto viene del sistema normal, ACMS.
  3. SQL
    SELECT q.reading_id, a.model, q.phase_of_flight, q.altitude_ft
FROM lab1002.cuarentena.fact_engine_sensor AS q
JOIN lab1002.silver.dim_aircraft AS a USING (aircraft_id)
WHERE q.altitude_ft > 50000;
    Deberías verCuatro lecturas de un B737-800 con altitudes de 340.000 a 380.000 pies —justo diez veces una altitud de crucero normal— y dos de un A350-900 con unos 62.000 pies.
    4. Comprueba que lo has entendido¿Cuáles de estos errores tienen una causa conocida y una corrección segura, y cuáles no? Un cero de más en un registrador concreto se puede deshacer. Una clave duplicada con dos matrículas distintas, no: alguien tiene que decidir cuál es la buena.

4La corrección como tarea del job10 min

Qué estás mirandoCorregir a mano sirve para entender. En producción, el notebook se ejecuta solo, justo después de las validaciones. Es una tarea de tipo Notebook que depende de cuatro tareas a la vez: no arranca hasta que terminan todas. El parámetro catalogo del job le llega al notebook automáticamente, como valor de su campo catalogo.
  3. Deberías verEn el lienzo, cuatro flechas que confluyen en corregir_cuarentena.
  4. Deberías verLas nueve tareas en verde. Al abrir corregir_cuarentena, el mismo resultado que a mano: 4 aeronaves y 8 lecturas reintegradas.
    5. Comprueba que lo has entendidoAcabas de lanzar el job por segunda vez y no se ha duplicado nada. ¿Por qué? Cada validación reescribe silver y cuarentena desde bronze (overwrite), así que cada ejecución parte de cero y el notebook vuelve a aplicar las mismas correcciones. Un job que se puede repetir sin efectos secundarios se llama idempotente, y es lo que permite relanzarlo tranquilo cuando algo falla.

5Claves y relaciones10 min

Qué estás mirandoCon silver limpio, puedes declarar el modelo: qué columna es la clave primaria de cada tabla y qué columnas apuntan a otras tablas (claves foráneas). En Databricks estas restricciones son informativas: no bloquean datos malos —para eso está la cuarentena—, pero documentan el modelo y Catalog Explorer las dibuja.
  1. SQL
    %sql
ALTER TABLE lab1002.silver.dim_aircraft ALTER COLUMN aircraft_id SET NOT NULL;
ALTER TABLE lab1002.silver.dim_aircraft ADD CONSTRAINT pk_dim_aircraft PRIMARY KEY (aircraft_id);

ALTER TABLE lab1002.silver.dim_phase ALTER COLUMN phase_key SET NOT NULL;
ALTER TABLE lab1002.silver.dim_phase ADD CONSTRAINT pk_dim_phase PRIMARY KEY (phase_key);

ALTER TABLE lab1002.silver.dim_sensor_reading ALTER COLUMN reading_id SET NOT NULL;
ALTER TABLE lab1002.silver.dim_sensor_reading ADD CONSTRAINT pk_dim_sensor_reading PRIMARY KEY (reading_id);

ALTER TABLE lab1002.silver.fact_engine_sensor ALTER COLUMN reading_id SET NOT NULL;
ALTER TABLE lab1002.silver.fact_engine_sensor ALTER COLUMN aircraft_id SET NOT NULL;
ALTER TABLE lab1002.silver.fact_engine_sensor ALTER COLUMN phase_of_flight SET NOT NULL;
ALTER TABLE lab1002.silver.fact_engine_sensor ADD CONSTRAINT pk_fact_engine_sensor PRIMARY KEY (reading_id);

ALTER TABLE lab1002.silver.fact_engine_sensor ADD CONSTRAINT fk_sensor_aircraft
  FOREIGN KEY (aircraft_id) REFERENCES lab1002.silver.dim_aircraft (aircraft_id);
ALTER TABLE lab1002.silver.fact_engine_sensor ADD CONSTRAINT fk_sensor_phase
  FOREIGN KEY (phase_of_flight) REFERENCES lab1002.silver.dim_phase (phase_key);
ALTER TABLE lab1002.silver.fact_engine_sensor ADD CONSTRAINT fk_sensor_reading
  FOREIGN KEY (reading_id) REFERENCES lab1002.silver.dim_sensor_reading (reading_id);
    OjoHazlo al final. Si después vuelves a lanzar el job, las validaciones reescriben las tablas de silver y puedes tener que repetir este bloque.
  2. Deberías verEn la pestaña Overview, las columnas con sus etiquetas de clave: PK en reading_id y FK en aircraft_id y phase_of_flight.
  3. Deberías verEl diagrama del modelo en estrella: la tabla de hechos en el centro unida a sus tres dimensiones.
    4. Si algo fallaSi SET NOT NULL falla porque la columna tiene nulos, el job no se ejecutó con la validación: relánzalo y repite. Si View relationships no aparece, recarga la página: las restricciones tardan unos segundos en verse.
