1Inmutabilidad5 min

Qué estás mirandoNinguna operación modifica el DataFrame original. Reasignar la variable no es modificar el objeto: como en Python, x = 5; x = x + 1 no cambia el 5, crea un 6.
  1. Python
    %python
df = spark.range(0, 20, 1, numPartitions=4).selectExpr(
    "id AS col1", "id * 2 AS col2", "id * 3 AS col3")

df_original = df
df = df.select("col1", "col2")          # objeto NUEVO: el original no se toca

print("Columnas de df_original:", df_original.columns)   # sigue con las 3
print("Columnas de df:         ", df.columns)            # solo 2
print("¿Es el mismo objeto?    ", df is df_original)     # False
    Por qué estoEl select no ha recortado nada ni ha copiado datos: ha creado un DataFrame nuevo, que es un paso más en un plan. Por eso encadenar transformaciones no cuesta memoria.
    Deberías verdf_original sigue con 3 columnas, df tiene 2 y ¿Es el mismo objeto? False.
  2. Python
    %python
# Lo mismo con un filter: el original no pierde filas.
# count() es una acción (lanza trabajo): aquí solo la usamos para comprobarlo; la explicamos en el bloque 5.
base = spark.range(0, 10)
filtrado = base.filter("id >= 5")

print("Filas en base:    ", base.count())      # sigue teniendo 10
print("Filas en filtrado:", filtrado.count())  # 5

    Deberías verFilas en base: 10 y Filas en filtrado: 5.

3Práctica 2 · Nada se ejecuta (Token · Clean)7 min

Qué estás mirandoCinco transformaciones narrow que trocean y limpian el texto. Cada una devuelve un DataFrame nuevo y solo añade un paso al plan.
  1. Python
    %python
from pyspark.sql.functions import col, split, explode, lower, regexp_extract

lines = book.select(split(col("value"), " ").alias("line"))          # Token
words = lines.select(explode(col("line")).alias("word"))
words_lower = words.select(lower(col("word")).alias("word_lower"))   # Clean
words_clean = words_lower.select(
    regexp_extract(col("word_lower"), "[a-z]+", 0).alias("word")
)
words_nonull = words_clean.filter(col("word") != "")
    Deberías verLa celda termina al instante y no imprime nada: no se ha leído ni una línea.
  2. Python
    %python
# El plan crece; el libro aún no se ha leído. explain() no es una acción.
words_nonull.explain(mode="formatted")
    Por qué estoexplain() no es una acción: enseña el plan sin ejecutarlo. En Databricks los nombres pueden empezar por Photon (PhotonProject…): es el motor vectorizado, la idea es la misma.
    Deberías verUn bloque == Physical Plan == con una lista numerada de operadores: la lectura de los datos locales (LocalTableScan), un Generate (el explode), los Project y el Filter.

4Cómo reescribe Spark tu plan15 min

Qué estás mirandoComo nada se ejecuta hasta la acción, Spark tiene tu cadena entera delante y puede mejorarla antes de mover un byte. Lo vas a ver escribiendo a propósito un plan malo y leyendo los cuatro planes por los que pasa.
ParsedTu código, tal cual. No comprueba nada
→
AnalyzedColumnas y tipos comprobados
→
OptimizedCatalyst funde, reordena y elimina
→
PhysicalCómo se ejecuta: operadores reales
  1. Python
    %python
from pyspark.sql import functions as F

df = (spark.range(1000)                              # id: 0..999
      .withColumn("v", F.rand(seed=42))              # aleatorio entre 0 y 1
      .withColumn("w", F.col("v") * 2))              # derivada

# Cadena de solo transformaciones narrow, con filtros redundantes
df_plan = (df
    .filter(F.col("v") > 0.10)
    .filter(F.col("v") > 0.15)
    .filter(F.col("v") > 0.20)
    .filter(F.col("v") < 0.95)
    .filter((F.col("id") % 2) == 0)
    .withColumn("z", F.col("w") + 1)
    .select("id", "z")                               # proyección: w y v ya no se piden
    .filter(F.col("z") > 1.2))
    Deberías verLa celda termina al instante: solo has descrito la receta.
  2. Python
    %python
# Los cuatro planes, de arriba abajo
df_plan.explain(mode="extended")
    Deberías verCuatro secciones, en este orden: == Parsed Logical Plan ==, == Analyzed Logical Plan ==, == Optimized Logical Plan == y == Physical Plan ==.
    3. PlanQué buscarQué significa
    ParsedLos seis Filter apilados, uno por cada .filter(), y columnas con comilla ('v, 'id) y unresolvedstarSpark ha traducido tu código sin comprobar nada: todavía no sabe si v existe
    AnalyzedEl mismo árbol, igual de largo, pero cada columna con su número (v#11066) y su tipo (id: bigint, z: double)Columnas y tipos validados. Si una columna no existiera, fallaría aquí, antes de leer una fila
    OptimizedUn solo Filter: (v > 0.2) AND (v < 0.95) AND (id % 2 = 0) AND (v * 2.0 + 1.0 > 1.2)Catalyst ha fundido los filtros, ha borrado v > 0.10 y v > 0.15 (los cubre v > 0.2), ha sustituido w y z por su fórmula y ha quitado la columna w
    PhysicalRange, Project y Filter (en Databricks, PhotonRange, PhotonProject, PhotonFilter) en un solo stageLo que se ejecuta de verdad: una pasada, sin pasos intermedios
    Catalyst no es magiaFíjate en el último filtro del plan optimizado, v × 2 + 1 > 1,2. Equivale a v > 0,1, y eso ya lo garantiza v > 0,2: el filtro sobra. Aun así, Catalyst no lo quita, porque no hace álgebra. Funde y elimina lo que reconoce por reglas; no razona como tú.
  3. Python
    %python
# La misma consulta, escrita limpia: un solo filtro y sin la columna w
limpio = (df
    .filter((F.col("v") > 0.20) & (F.col("v") < 0.95) & ((F.col("id") % 2) == 0))
    .select("id", (F.col("v") * 2 + 1).alias("z"))
    .filter(F.col("z") > 1.2))

limpio.explain()      # solo el plan físico: compáralo con el de df_plan
    Por qué estoMoraleja práctica: escribe el código para que se lea bien. Separar filtros o crear columnas intermedias no hace más lento tu programa, porque Catalyst lo reescribe. Lo que sí cuesta es lo que no puede quitar, como pedir columnas que no necesitas al final.
    Deberías verUn plan físico con los mismos operadores y las mismas condiciones que el de df_plan.
    4. Comprueba que lo has entendido¿Por qué Spark puede quitar la columna w y fundir los filtros, y pandas no podría? Pista: piensa en qué tiene delante cada uno en el momento de ejecutar la primera línea.

from pyspark.sql import functions as F

df = spark.range(0, 120, 1, numPartitions=4).selectExpr(
    "id % 3 AS categoria",
    "CASE WHEN id % 2 = 0 THEN id END AS valor",
)

resultado = df.groupBy("categoria").count()

print("Filas: ", n_filas)      # 120

ExtraSi sobra tiempo · 8 particiones5 min

Qué estás mirandoEn serverless no eliges los núcleos, pero sí cuántas particiones tiene un DataFrame. Con spark_partition_id ves cuántas filas caen en cada una.
  1. Python
    %python
from pyspark.sql.functions import spark_partition_id, sum as spark_sum

df8 = spark.range(0, 8000, 1, numPartitions=8)
df8.explain(mode="formatted")

reparto = (df8
           .select(spark_partition_id().alias("particion"))
           .groupBy("particion")
           .count()
           .orderBy("particion"))
reparto.show()

print("Suma de id:", df8.agg(spark_sum("id")).first()[0])
    Por qué estoCon 4 núcleos, 8 particiones irían en dos oleadas de 4. En serverless no afirmamos los núcleos: después de la acción, míralo en el Query Profile.
