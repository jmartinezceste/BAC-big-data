2Cargar el histórico con CTAS8 min

Qué estás mirandoCTAS es CREATE TABLE AS SELECT: crear una tabla con el resultado de una consulta. Hasta ahora solo leías los ficheros; esto escribe los datos en una tabla Delta propia, independiente del volumen.
  1. SQL
    %sql
CREATE OR REPLACE TABLE historical_users_bronze_ctas_rf
USING DELTA
AS SELECT *
FROM read_files(
    '/Volumes/lab0501/upload/upload/users-historical',
    format => 'parquet'
);

SELECT count(*) AS filas
FROM historical_users_bronze_ctas_rf;
    Por qué estoCREATE OR REPLACE permite repetir la celda: cada vez reconstruye la tabla entera desde los ficheros.
    Deberías ver251501 filas, las mismas que el origen.
  2. SQL
    %sql
DESCRIBE TABLE EXTENDED historical_users_bronze_ctas_rf;
    Deberías verEn Detailed Table Information: Type = MANAGED, Provider = delta y una Location que no es la ruta del volumen.
    3. Comprueba que lo has entendidoSi mañana llega un quinto fichero a la carpeta, ¿aparece solo en la tabla? No: el CTAS se ejecutó una vez y la tabla no queda conectada a la carpeta. Para incluirlo tendrías que repetir el CTAS, que recarga las 251.501 filas otra vez.
    Si algo fallaSi el CTAS falla con un error de permisos, no puedes crear tablas en lab0501.bronze: avisa al docente. Si sigue sin funcionar, salta al bloque 3.

3La misma carga en PySpark5 min

Qué estás mirandoLa API de DataFrames hace lo mismo que el CTAS: leer, escribir una tabla Delta y consultarla. mode("overwrite") equivale al CREATE OR REPLACE: tampoco recuerda qué ficheros cargó.
  1. Python
    %python
RUTA_ORIGEN = "/Volumes/lab0501/upload/upload/users-historical"
TABLA_PYTHON = "lab0501.bronze.historical_users_bronze_python"

df = spark.read.format("parquet").load(RUTA_ORIGEN)

(df.write
   .format("delta")
   .mode("overwrite")
   .saveAsTable(TABLA_PYTHON))

users_bronze_table = spark.table(TABLA_PYTHON)
users_bronze_table.printSchema()
print("filas:", users_bronze_table.count())
display(users_bronze_table.limit(10))
    Deberías verEl esquema con tres columnas, filas: 251501 y una muestra de diez filas. Aquí no aparece _rescued_data: es propia de read_files.
    2. Si algo fallaSi la celda falla con NameError: spark, el notebook no está conectado a Serverless. Si sigue sin funcionar, salta al bloque 4: no depende de esta tabla.

4COPY INTO y el error de esquema12 min

Qué estás mirandoCOPY INTO carga ficheros en una tabla que ya existe y recuerda cuáles ha cargado. Pero la tabla manda: si los ficheros traen una columna que la tabla no tiene, la carga falla, salvo que permitas que el esquema evolucione.
  1. SQL
    %sql
CREATE OR REPLACE TABLE historical_users_bronze_ci (
    user_id STRING,
    user_first_touch_timestamp BIGINT
);
    Deberías verLa celda termina sin resultado: la tabla está creada y vacía.
  2. SQL
    %sql
COPY INTO historical_users_bronze_ci
FROM '/Volumes/lab0501/upload/upload/users-historical'
FILEFORMAT = PARQUET
    Deberías verLa celda termina con un error COPY_INTO_SCHEMA_MISMATCH_WITH_TARGET_TABLE. Es lo esperado. Los ficheros traen email y la tabla no tiene esa columna.
  3. SQL
    %sql
COPY INTO historical_users_bronze_ci
FROM '/Volumes/lab0501/upload/upload/users-historical'
FILEFORMAT = PARQUET
COPY_OPTIONS ('mergeSchema' = 'true');
    Deberías verUna fila de resultado con num_affected_rows y num_inserted_rows = 251501.
  4. SQL
    %sql
SELECT *
FROM historical_users_bronze_ci
LIMIT 10;
    Deberías verTres columnas: email se ha añadido sola.
  5. SQL
    %sql
DROP TABLE IF EXISTS historical_users_bronze_ci_no_schema;

CREATE TABLE historical_users_bronze_ci_no_schema;

COPY INTO historical_users_bronze_ci_no_schema
FROM '/Volumes/lab0501/upload/upload/users-historical'
FILEFORMAT = PARQUET
COPY_OPTIONS ('mergeSchema' = 'true');
    Deberías vernum_inserted_rows = 251501.
    6. Si algo fallaSi el primer COPY INTO no da error, la tabla tenía ya la columna email: vuelve a ejecutar su CREATE OR REPLACE y repite. Si un COPY INTO inserta 0 filas a la primera, la tabla viene de una ejecución anterior: ejecuta 00_preparar_entorno y vuelve a empezar este bloque. Si sigue sin funcionar, salta al bloque 5.

5Repetir la carga no duplica7 min

Qué estás mirandoUna operación es idempotente si repetirla deja el mismo resultado. COPY INTO lo es porque guarda la lista de ficheros que ya cargó en cada tabla: si los vuelves a pedir, los salta.
  1. SQL
    %sql
COPY INTO historical_users_bronze_ci_no_schema
FROM '/Volumes/lab0501/upload/upload/users-historical'
FILEFORMAT = PARQUET
COPY_OPTIONS ('mergeSchema' = 'true');
    Deberías vernum_affected_rows, num_inserted_rows y num_skipped_corrupt_files a 0.
  2. SQL
    %sql
SELECT count(*) AS filas
FROM historical_users_bronze_ci_no_schema;
    Deberías ver251501, no el doble.
  3. SQL
    %sql
DESCRIBE HISTORY historical_users_bronze_ci_no_schema;
    Deberías verUna operación COPY INTO con numOutputRows = 251501 en operationMetrics. La segunda ejecución no escribió nada: según la versión, aparece con 0 filas o no genera versión nueva.
    4. Comprueba que lo has entendido¿Evita COPY INTO cualquier duplicado? No: controla ficheros, no claves. Si llega un fichero nuevo con un usuario que ya existía, se cargará. Quitar duplicados por clave es otra regla que se aplica aparte.
    Si algo fallaSi la repetición inserta filas, se ha recreado la tabla entre medias: repite el paso 5 del bloque 4 y después este bloque. Si sigue sin funcionar, da el laboratorio por terminado y repasa los recuadros Comprueba que lo has entendido.
