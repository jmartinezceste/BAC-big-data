2Nivel 2 · Lo que funciona distinto13 min

Qué estás mirandoAquí es donde se rompe el modelo mental de pandas. No son más métodos que memorizar: son cuatro ideas que cambian cómo piensas el código. Si estas cuatro te entran, el resto de PySpark se deduce solo.
  1. Python
    %python
# pandas: esto calcula y devuelve datos
caro_pd = pdf[pdf["precio"] > 100]
print("pandas ya tiene", len(caro_pd), "filas")

# PySpark: esto NO calcula nada todavía
caro_sdf = sdf.filter(F.col("precio") > 100)
print("spark devuelve:", caro_sdf)
    Por qué estoEn pandas, cada línea se ejecuta cuando la escribes. En Spark, filter solo anota lo que quieres. Nada se calcula hasta que pides un resultado de verdad: eso se llama una acción, y son show(), count(), collect(), toPandas(), escribir una tabla… Todo lo demás son transformaciones, y son gratis.
    Deberías verpandas imprime 3 filas. Spark imprime un DataFrame[fecha: string, ...] — la descripción de un plan, no unos datos.
  2. Python
    %python
caro_sdf.show()
    Deberías verAhora sí salen las tres filas de Monitor. Y esta celda ha tardado bastante más que la anterior: es donde ha ocurrido el trabajo de verdad.
  3. Python
    %python
# En pandas esto es lo normal:
pdf["total"] = pdf["cantidad"] * pdf["precio"]
pdf.head(3)

# En Spark esto NO funciona. Descoméntalo si quieres verlo fallar:
# sdf["total"] = sdf["cantidad"] * sdf["precio"]
    Por qué estoUn DataFrame de Spark es inmutable: no se le pueden añadir columnas por asignación, y no existe inplace=True. Cada operación devuelve un DataFrame nuevo. Por eso el código de PySpark se escribe encadenado.
    OjoEsta es la costumbre de pandas que más cuesta soltar, y la que más errores raros provoca al empezar.
  4. Python
    %python
sdf = sdf.withColumn("total", F.col("cantidad") * F.col("precio"))
sdf.select("producto", "cantidad", "precio", "total").show(5)
    Por qué estoFíjate en el sdf = sdf.withColumn(...): hay que reasignar, porque el original no se toca. Si te olvidas del sdf =, la columna se calcula, se devuelve y se pierde.
    Deberías verLa columna total, con 90.0 en la primera fila (12 × 7,50).
  5. Python
    %python
# pandas: una Serie, con los valores dentro
print(pdf["precio"].head(3).tolist())

# PySpark: una expresión que todavía no se ha calculado
print(F.col("precio"))
print(F.col("precio") * 2)
    Por qué estoEn pandas, pdf["precio"] son los datos. En Spark, F.col("precio") es una receta: «la columna que se llama precio». Por eso puedes multiplicarla por 2 sin que exista ningún dato todavía. Entender esto es entender por qué Spark puede optimizar tu código antes de ejecutarlo.
    Deberías verpandas imprime [7.5, 199.99, 25.99]. Spark imprime Column<'precio'> y Column<'(precio * 2)'> — descripciones, no valores.
  6. Python
    %python
# Esto falla: Spark espera una columna, y le das un texto suelto
# sdf.withColumn("moneda", "EUR").show(3)

# Así sí: F.lit() convierte un valor fijo en una columna
sdf.withColumn("moneda", F.lit("EUR")).select("producto", "moneda").show(3)
    Por qué estoF.lit() significa literal. Todo lo que withColumn recibe tiene que ser una columna; un texto o un número sueltos no lo son, así que hay que envolverlos para convertir «EUR» en «una columna que vale EUR en todas las filas». En pandas esto es automático: pdf["moneda"] = "EUR" y ya está.
    OjoCuando veas el error Column is not iterable o col should be Column, casi siempre te falta un F.lit().
    Deberías verTres filas con EUR en la columna nueva.
  7. Python
    %python
# En pandas esto es el pan de cada día:
print(pdf.loc[0, "producto"])
print(pdf.iloc[3])

# En Spark no existe .loc, ni .iloc, ni set_index().
# Lo más parecido es pedir las primeras n filas:

    Deberías verpandas responde Alfombrilla sin dudar. Spark te devuelve una lista con un Row(...) — y no te promete que sea siempre el mismo.

3Nivel 3 · Los mandos que pandas no tiene13 min

Qué estás mirandoHasta aquí has traducido. Ahora vienen cuatro herramientas que no tienen equivalente cómodo en pandas, y que son las que hacen que merezca la pena escribir PySpark en vez de hacerlo todo en SQL o en pandas.
  1. Python
    %python
# pandas: normalmente con np.where o con .apply()
pdf["gama"] = pdf["precio"].apply(lambda p: "alta" if p > 100 else "baja")

# PySpark: when / otherwise
sdf = sdf.withColumn(
    "gama",
    F.when(F.col("precio") > 100, "alta").otherwise("baja")
)
sdf.select("producto", "precio", "gama").show(5)
    Por qué estoAquí hay una lección escondida: en Spark evita .apply() con funciones de Python. Obliga a sacar cada fila de Spark, pasarla por Python y devolverla, y eso tira abajo todo el rendimiento. when/otherwise se ejecuta dentro del motor, sin salir.
    Deberías verMonitor como alta y el resto como baja.
  2. Python
    %python
sdf.select(
    "producto",
    "precio",
    F.expr("CASE WHEN precio > 100 THEN 'alta' ELSE 'baja' END AS gama_sql"),
    F.expr("ROUND(cantidad * precio, 2) AS total_sql")
).show(5)
    Por qué estoF.expr() es la puerta de escape: le pasas un trozo de SQL como texto y Spark lo entiende igual que si lo hubieras escrito con la API. Sirve para lo que en la API queda largo, y para traducir consultas que ya tenías escritas en SQL.
    Deberías verLas mismas dos columnas del paso anterior, calculadas con SQL escrito dentro de un select de Python.
  3. Python
    %python
sdf.selectExpr(
    "producto",
    "cantidad * precio AS total",
    "upper(pais) AS pais_mayus"
).show(5)
    Deberías verLas tres columnas, con el país en mayúsculas.
  4. Python
    %python
from pyspark.sql import Window

ventana = Window.partitionBy("categoria").orderBy(F.desc("total"))

sdf.withColumn("puesto", F.row_number().over(ventana)) \
   .select("categoria", "producto", "total", "puesto") \
   .orderBy("categoria", "puesto") \
   .show()
    Por qué estoUn groupBy te devuelve una fila por grupo y pierdes el detalle. Una ventana calcula lo mismo pero deja todas las filas en su sitio, añadiendo el resultado como una columna más. Es la herramienta para rankings, acumulados y comparaciones contra el propio grupo.
    Deberías verDentro de cada categoría, los productos numerados 1, 2, 3… por importe. Ninguna fila ha desaparecido.
  5. Python
    %python
sdf.createOrReplaceTempView("ventas")

spark.sql("""
    SELECT pais,
           ROUND(SUM(total), 2) AS facturado
    FROM ventas
    GROUP BY pais
    ORDER BY facturado DESC
""").show()
    Por qué estoNo hay conversión ni copia: es el mismo DataFrame, consultado con otro lenguaje. Puedes empezar en Python, pasar a SQL para la parte que te salga mejor en SQL, y volver. En pandas esto no existe sin montar una base de datos aparte.
    Deberías verTres países ordenados por facturación.
  6. Python
    %python
sdf.filter(F.col("precio") > 20) \
   .groupBy("categoria") \
   .agg(F.sum("total").alias("facturado")) \
   .explain()
    Por qué estoexplain() te enseña lo que Spark va a hacer, no lo que ha hecho. Ahí está la respuesta al checkpoint anterior: encadenar diez transformaciones no recorre los datos diez veces — Spark junta todo el encadenado en un solo plan y lo recorre una vez, reordenando por el camino lo que puede.
    Deberías verUn plan físico con sus etapas. No hace falta que lo entiendas entero: lo que importa es que exista, y que se pueda mirar.
    7. Si algo fallaSi el Window te falla, comprueba que ejecutaste el paso de withColumn("total", ...) del nivel 2: la ventana ordena por esa columna.
