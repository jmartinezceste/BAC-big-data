2Crear la streaming table10 min

Qué estás mirandoUna streaming table es una tabla de Unity Catalog que se mantiene al día de forma incremental: en cada refresco solo procesa lo nuevo. Al crearla, Databricks monta por ti un pipeline serverless que hace el trabajo; no consume el cómputo de tu notebook. Es la alternativa recomendada al COPY INTO del laboratorio 0501.
  1. SQL
    %sql
CREATE OR REFRESH STREAMING TABLE lab0502.streaming.sql_csv_autoloader
--SCHEDULE EVERY 1 WEEK     -- Optional: slower to create, keep commented in this lab
AS
SELECT *
FROM STREAM read_files(
  '/Volumes/lab0502/upload/upload',
  format => 'CSV',
  sep => '|',
  header => true
);
    Por qué estoSTREAM delante de read_files es lo que la hace incremental: el lector recuerda qué ficheros ha procesado. SCHEDULE la refrescaría sola cada semana; es opcional y aquí la dejamos comentada porque con ella la creación tarda un poco más. El nombre completo lab0502.streaming… evita que la tabla acabe en otro catálogo si cambias de compute y se pierde el USE CATALOG.
  2. Deberías verLa tabla sql_csv_autoloader, con un icono distinto al de una tabla normal: una tabla con unas ondas.
  3. SQL
    %sql
SELECT *
FROM lab0502.streaming.sql_csv_autoloader;
    Deberías ver3.149 filas.
  4. SQL
    %sql
DESCRIBE TABLE EXTENDED lab0502.streaming.sql_csv_autoloader;
    Deberías verEn Detailed Table Information, Type indica que es una streaming table y Provider = delta. Más abajo, Refresh Information con el último refresco. Como el SCHEDULE está comentado, no verás una programación semanal.
  5. SQL
    %sql
DESCRIBE HISTORY lab0502.streaming.sql_csv_autoloader;
    Deberías verTres operaciones, ordenadas de la más reciente a la más antigua:
    versionoperationQué significa
    2STREAMING UPDATEAuto Loader ha leído los CSV del volumen y los ha escrito en la tabla
    1DLT SETUPEl pipeline interno prepara la tabla (esquema y metadatos)
    0CREATE TABLESe crea la tabla vacía en Unity Catalog
    En la fila STREAMING UPDATE, desplázate hasta operationMetrics: numOutputRows = 3149, las filas de 000.csv.
    ¿Por qué aparece “DLT”?Una streaming table creada desde SQL se gestiona con un pipeline serverless de Lakeflow Declarative Pipelines (antes llamado Delta Live Tables, DLT), que Databricks crea automáticamente. No lo ves en tu notebook, pero puedes encontrarlo en Jobs & Pipelines. 💡 Si vuelves a ejecutar el CREATE OR REFRESH sin ficheros nuevos, no se cargan filas duplicadas: Auto Loader recuerda en el checkpoint qué ficheros ya ha procesado.

Si sale CF_PARTITON_INFERENCE_ERROR o el historial tiene más operaciones de las esperadas, queda una tabla de un intento anterior: ejecuta DROP TABLE IF EXISTS lab0502.streaming.sql_csv_autoloader; y vuelve a crearla. +Extra: Auto Loader en Python15 min

Qué estás mirandoLo que la streaming table hace por debajo lo puedes escribir tú con Structured Streaming: el formato cloudFiles es Auto Loader. Necesitas una carpeta de checkpoint, donde Auto Loader apunta qué ficheros ha procesado. Este bloque es material extra: hazlo si te sobra tiempo. Todo es Python: conecta tu notebook a Serverless.

  3. Python
    %python
checkpoint_file_location = '/Volumes/lab0502/streaming/checkpoints/python_csv_autoloader'

(spark
 .readStream
   .format("cloudFiles")
   .option("cloudFiles.format", "csv")
   .option("header", "true")
   .option("sep", "|")
   .option("inferSchema", "true")
   .option("cloudFiles.schemaLocation", f"{checkpoint_file_location}")
   .load("/Volumes/lab0502/upload/upload/")
 .writeStream
   .option("checkpointLocation", f"{checkpoint_file_location}")
   .trigger(availableNow=True)
   .toTable("lab0502.streaming.python_csv_autoloader")
 .awaitTermination()
)
    Por qué estoavailableNow=True procesa lo pendiente y se para. El trigger(once=True) de muchos tutoriales hace lo mismo, pero está deprecado y Serverless no lo admite.
  4. SQL
    %sql

FROM lab0502.streaming.python_csv_autoloader;
    Deberías ver3.149 filas y todas las columnas como texto, aunque el código pide inferSchema. Auto Loader ignora esa opción; para inferir tipos se usa cloudFiles.inferColumnTypes.
